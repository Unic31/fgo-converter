## 2. 컨버터 (`src/routes/converter/+page.svelte`)

### 웨이브 처리
- 변환할 때 Atlas Academy `GET /nice/JP/quest/{id}/{phase}`의 `stages` 개수로 웨이브 수(`waveCount`)를 구합니다. 조회에 실패하면 `null`이고, 이때는 예전처럼 `,#,` 기본값에 토글도 그대로 동작합니다.
- **웨이브 1개** (`isSingleWave`, 관위전·레이드): 모든 턴 전환이 `,`(동일 웨이브 다음턴)로 고정되고 토글이 막힙니다.
- **전환 횟수 = 웨이브 수 − 1** (`isAllNextWave`, 예: 3웨이브 3턴클): 모든 전환이 `,#,`(다음 웨이브)로 고정되고 토글이 막힙니다.
- 두 경우를 묶어 `isSeparatorLocked`로 토글을 차단합니다.
- 확인한 퀘스트: `94137202` 월광 채굴장(2웨이브), `94145437` 관위연찬전 세이버 Ⅶ(1웨이브), `94141608` 컨시어지 일지(3웨이브).
- 턴 전환 횟수는 공격(`attack`) 액션 하나가 한 턴이라서, 구분자 개수 = 공격 횟수 − 1입니다.

### 안내 표시
- 구분자 위 말풍선과 "웨이브 안내" 토글 버튼, 말풍선용 여백을 제거했습니다.
- "변환된 커맨드" 제목 오른쪽에 범례를 두었습니다: `,#, : 다음 웨이브` / `, : 동일 웨이브 다음턴`.
- 퀘스트 구조상 쓰이지 않는 쪽은 흐리게 + 취소선으로 표시합니다 (1웨이브면 `,#,`, 전환 횟수가 맞으면 `,`).
- localStorage `converter_show_wave_tooltip`은 더 이상 읽거나 쓰지 않습니다. 이전에 저장된 값이 남아 있어도 영향이 없습니다.

### 개발용 URL 패널 (`src/lib/devUrls.js`)
- 개발 환경(`dev`)에서만 보이는 블록에 "저장된 테스트 URL" 패널이 있고, 항목마다 `변환` 버튼이 있어 해당 URL로 바로 변환합니다.
- URL은 `{ label, url }` 배열로 기록합니다. 새 케이스는 항목만 추가하면 됩니다.

## 4. 체크리스트 — 데이터

### 저장 형태 (`localStorage multi_accounts` → `svt_data[collectionNo]`)

```
{ npLv, grail?, isGrand?, bond? }
```

- `npLv`가 보유 표시입니다(`>= 1`이면 보유).
- `grail`은 성배 **사용 개수**, `isGrand`는 관위 여부, `bond`는 인연 포인트(0~16)입니다.
- `grail` / `isGrand` / `bond`는 **해당될 때만 저장**하고, 없으면 0/false와 같은 뜻입니다.
- 예전 데이터의 `isGrail: true/false`는 그대로 읽을 수 있고, 일괄 변환하지 않습니다.

### 데이터 호환 원칙
- 기존 사용자 localStorage 값이 사라지지 않는 것이 최우선 조건입니다.
- 새 필드는 선택 필드로만 추가하고, 기존 저장값의 의미는 바꾸지 않습니다.
- 읽을 때는 `=== false` 비교를 쓰지 않고 참/거짓으로만 판정합니다.
- 설정값(`svt_checklist_settings`)의 기존 값(`click`, `decrease`)도 의미를 유지합니다.
- 규칙은 [CLAUDE.md](../CLAUDE.md)의 "체크리스트 데이터 규격"에도 반영했습니다.

### 칼데아 JSON 가져오기 (`parseChaldeaUserdata`, `importJSON`)
- `users[curUserKey].servants[collectionNo]`에서 읽고, 체크리스트 대상(5성)이면서 `cur.favorite`인 서번트만 가져옵니다.
- `grail = cur.grail`(0이면 생략), `isGrand = grandSvt`, `bond = servants[id].bond`(`cur` 안이 아니라 서번트 항목 바로 아래, 0~16으로 정리하고 0이면 생략).
- **빈 가져오기 방지:** 가져올 보유 서번트가 0개면 기존 데이터를 지우지 않습니다.
- **백업:** 가져오기 직전의 전체 계정 데이터를 `multi_accounts_backup_before_import`에 저장합니다(가장 최근 1회분).
- 가져오기는 여전히 현재 계정을 통째로 교체합니다(병합은 아직 없음).

### 성배 (`src/lib/grail.js`)
- 5성은 성배 1개당 레벨 +2입니다. **5개 = Lv100, 15개 = Lv120(최대)**.
- 근거: 사용자 JSON에서 모르간(309)·스페이스 이슈타르(268)가 15개, 시엘 "Mysterious Executor C.I.E.L"(418)·Archetype: Earth(351)가 5개이고, 5개인 서번트 11명이 모두 Lv100으로 보입니다. 체크리스트 대상 200명은 전부 5성입니다.
- `getGrail(state)`는 개수를 읽고, `grail`이 없을 때만 예전 `isGrail: true`를 5개로 해석합니다.
- `grailTier(state)`는 `0 / 100 / 120`을 돌려줍니다 (`GRAIL_100 = 5`, `GRAIL_120 = 15`).
- 표시: 100이면 `grail100.png`, 120이면 `grail120.png` (예전 `grail12.png` / `grail13.png`에서 이름 변경).
- 클릭 순환: **없음 → 100(5개 저장) → 120(15개 저장) → 없음(필드 삭제)**. 중간 개수는 다음 단계로 이어집니다(9개→15개, 20개→없음, 1~4개→5개). 성배 칸 우클릭과 "성배" 옵션도 같은 방향으로 순환합니다.
- 센지 무라마사(302)는 Lv100이라고 하셨지만 JSON에는 성배 0개입니다(칼데아 앱 입력 누락으로 추정).

## 5. 체크리스트 — 관위 테두리

- 관위(`isGrand`)를 켠 **보유** 서번트 타일에 테두리를 둘러 가시성을 높였습니다. 클릭은 통과합니다(`pointer-events-none`).
- 겹침 순서(아래가 위): 이미지 → 그라데이션(`z-0`) → **관위 테두리(`z-5`)** → 성배·관위·보구레벨 표시(`z-10`). 표시 데이터가 테두리보다 위에 옵니다.
- 커밋된 상태(`89c99bd`): 3px, `blue-500`.
- 색을 단계별로 시도했습니다: `#3b82f6` → `#1e90ff` → `#00b4ff`. 안쪽 1px 흰 선은 효과가 덜해서 뺐습니다.
- **미커밋 (현재 작업 트리):** 두께 `border-4`, 색은 클래스 폴더별 표(`grandBorderColors`)로 지정합니다. 비교용 임시 코드입니다.

|---|---|---|---|
| 세이버 | `#00b4ff` | 어벤저 | `#29bbff` |
| 아처 | `#2979ff` | 얼터에고 | `#5ccbff` |
| 랜서 | `#00e5ff` | 포리너 | `#1f9aff` |

- 세이버·아처·랜서·라이더는 어울린다고 하신 색 그대로이고, 나머지 11개는 같은 파랑~하늘색 계열(색조 186°~222°)에서 서로 구분되게(RGB 최소 거리 약 26), 아처보다 어둡지 않게 계산해서 골랐습니다.

## 6. 보류·삭제된 작업

- 클릭 옵션 확장: 좌클릭 `click`(구역) / `np`(보구) / `grail` / `grand` / `bond`, 우클릭 `zone`(구역: 눌린 구역대로) / `decrease`(보구, 기존 저장값 의미 유지) / `grail` / `grand` / `bond`.

## 8. 검증 방법과 한계

- 논리 검증은 node 스크립트로 했습니다. 사용자 JSON 3개(`chaldea-userdata-20261016T170304`, `...20261029T151444`, `...20261104T164554`)로 가져오기 결과를 원본 값과 대조했고(55개 가져옴, 인연 53개, 최대 14), 기존 형태 데이터를 읽고 클릭하는 시나리오와 성배 순환을 시뮬레이션했습니다.
- `npx svelte-check --threshold error`는 에러 0건입니다 (경고 18개는 기존 것).
- 개발 서버에서는 개발용 URL 패널과 `/icon` 페이지의 SSR 결과만 확인했습니다.
- **브라우저에서 직접 눌러 보거나 눈으로 확인한 것은 없습니다.** 관위 테두리 색, 모달 모양, 범례, 아이콘 크기별 모습은 화면에서 확인이 필요합니다. PNG 저장(`html-to-image`)에서의 테두리 표시도 미확인입니다.
